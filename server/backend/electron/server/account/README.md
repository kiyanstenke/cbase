# `account/` — account (usage and credit, providers and models)

**What lives here:** `usage.js`: usage and credit of the Claude account — credentials from the keychain, the `credentials` file or `CLAUDE_CODE_OAUTH_TOKEN` (`keychainCredential`, `credentialsFileCredential`, `claudeUsageCredential`), refresh through the CLI (`refreshClaudeCredentials`, `claude doctor`), `requestClaudeUsage` and the cached fetch with backoff `fetchUsageLimits`; plus `claudeAuth` (`claude auth status/logout`). The module-wide `let`s (cache, backoff, refresh in flight) are assigned only here. `credentialsCandidates(env, home)` puts `$CLAUDE_SECURESTORAGE_CONFIG_DIR/.credentials.json` first, only when the variable is set (image ENV of the user container; entry.sh moves the file there); `credentialsFileCredential` is exported for the guard `server/backend/test/login-directory.test.js`. `providers.js`: providers and models — `modelKnown` (the picker has no free text) and `defaultModelFor` (at home in `../providers/index.js` together with `DEFAULT_MODEL_FALLBACK` and only passed through here — the default effort level next to it needs it there, and the way back would be a cycle). `defaultModelFor` counts `visibleModels(p, …)`, not the raw catalog — it only returns a model the signed-in account kind can actually run (a default that cannot run is not a default). There are no third-party providers from the database: OpenRouter is built in (`../providers/connectors/openrouter.js`), its catalog loads itself (`../providers/openrouter-catalog.js`). `provider-migration.js`: the one-time migration of the store to the three providers (marker `migration.provider_only_three`) — the first OpenRouter row becomes `providers.openrouter`, every other provider is removed, its references (chats with a hint row, outer loop, agent definitions, run settings, app agents, global provider) migrate to the same model at OpenRouter (catalog + key) or to Claude; plus price table and Codex zero rows; at start after the catalog (at most 10 s), the dependent migrations run behind it as `afterwards`. Guard `server/backend/test/provider-migration.test.js`. `model-migration.js`: retired models migrate to their successor (table `../providers/retired.js`).

**Routes (`routes.js`):** `accountRoutes` — `/api/usage` (`/codex`, `/openrouter-prices`, `/run`, `/consumption`, `/history`, `/claude-limits`, `/openrouter-credit`, see "Usage and cost"), `/api/account` (`/connect`, `/logout`), `/api/providers`, `/api/default-model`, `/api/default-effort` (PUT: default effort level per provider under `default_effort_<id>`; missing or unknown `effort` ⇒ 400, `""` ⇒ back to the preset), `/api/provider`, `/api/openrouter` (GET/PUT/DELETE, contract `OPENROUTER_*` in `usage-contract.js`: GET only says WHETHER a key is set, plus the two privacy switches from `extra_body.provider` of the row `providers.openrouter`; PUT requires both switches as booleans, `apiKey` is optional, empty is a 400; DELETE removes the key — it never leaves the server). No route creates a provider; every route that takes an id rejects a foreign one with 400 (guard `server/backend/test/only-three-provider.test.js`). `codexRoutes` — `/api/account/:provider` (live connection check of OpenRouter or status of Claude, `codex` excluded; a foreign id is a 400), `/api/account/codex` (`/connect`, `/logout`) and the OAuth relay `/api/codex-oauth/*`. `let lastClaudeConnected` lives HERE — the `/api/providers` route assigns it, sole reader and writer; in another file the assignment would be a silent TypeError. **`/api/providers` is also what FILLS the visibility:** the route writes `setAccountKind(id, authMethod)` per provider (`../providers/index.js`) — BEFORE it enumerates models, because `visibleModels` and `defaultModelFor` one line below already depend on it. It is the filler because the clients poll it constantly anyway; asking would only work async, and `codex login status` has a 15 s timeout. The same assignment drives `subagentHosts`/`agentHosts` and with them every path that NAMES subagent models (system prompt, tool description, error hints). `POST /api/account/codex/logout` calls `forgetAccountKind("codex")`: the remembered account kind belongs to the logged-out account, and unknown means show EVERYTHING again. Every provider in `/api/providers` carries, besides `defaultModel`, `defaultEffort` (`../providers/index.js:effortStandard` — chosen, otherwise — if the default model is the fallback model — the fallback level `DEFAULT_EFFORT_FALLBACK`, otherwise the catalog level of the default model, otherwise `medium`; always a level, clamping happens only in the run) and `caps` (among them `caps.effort`: off ⇒ no level picker). `PUT /api/default-model` checks against `visibleModels` instead of the raw catalog and states the reason for a rejection in plain words ("needs an API key") — "unknown" would be wrong, the model does exist; for OpenRouter it accepts any catalog model with tools (`modelSelectable`, an empty catalog is unknown). In `/api/providers` OpenRouter carries the catalog list (only models with tools) and is "connected" when a key is set.

**What does NOT live here:** the model catalog (`../providers/connectors/claude.js`, `…/codex.js`) and the registry (`../providers/index.js`) — the visibility rule itself lives there too (`setAccountKind`, `forgetAccountKind`, `visibleModels`); `account/` fills and reads it —, limit detection in the run (`../limits.js`), Codex usage (`providers/index.js:codexUsage`, from the session file) and the credit gates of the runs (`runs/limit-gate.js`).

**Terms (→ file):** usage, credit, limit window, OAuth token, refresh → `usage.js` · provider, model, default model → `providers.js` · migration to three providers → `provider-migration.js` · account status, connection check, OpenRouter access, Codex OAuth relay → `routes.js` · consumption, window, history, credit → `usage-report.js` (fields: `usage-contract.js`) · API equivalent → `equivalent.js` · inquiring/estimating OpenRouter amounts → `openrouter-inquiry.js` · cost of a run → `prices.js`.

**The three most common questions:**
- Where does the percentage in the top navigation come from, and why is it sometimes old? → `usage.js:fetchUsageLimits` (cache 60 s, cooldown after 429 per `Retry-After`, `force` for auto-continue).
- Why does the server not renew the token itself? → `usage.js:refreshClaudeCredentials` (the CLI rotates the refresh token; a refresh of our own would log Claude Code out).
- Which model runs when a chat or oneshot carries none, and can an id be chosen at all? → `providers.js:defaultModelFor` (source `../providers/index.js`, also asked there by `runOnce` and `effortStandard`) / `providers.js:modelKnown`. The first answer depends on the ACCOUNT KIND that `routes.js` stored via `setAccountKind`; the second deliberately does not — `modelKnown` only checks whether the catalog knows the id (it protects a workflow definition from a typo, and that may come from a machine with another account).

**Usage and cost (contract `usage-contract.js`):**
the "Usage" page reads four routes, computed in `usage-report.js` (so the guard can run them without a server): `GET /api/usage/consumption`
(per provider and window; the windows `session`/`week` from the LAST snapshot — Claude `usage_cache_v1` via
`usage.js:usageInMemory`, Codex `codexUsage()` from the rollouts —, NEVER a fetch: no `fetchUsageLimits`, no `claude doctor`; without a
snapshot sliding with `windowKnown: false`; at most 25 chats, the rest in `chatsAdditional`), `/history` (gapless per calendar day
in the client's time zone, `offsetMin`), `/claude-limits` (only the snapshot) and `/openrouter-credit` (live from `/credits` and
`/key`, cached 60 s; without a key everything null). The headline number of the subscription providers is the API equivalent
(`equivalent.js`, a leaf: prices from the OpenRouter catalog, Claude write = 2 × input, Codex write = 0; a cache without a split or a
model without a price makes it incomplete, never 0). OpenRouter has cost with an origin (`COST_ORIGIN`): `reported` (the response
carried `usage.cost`, `../providers/connectors/consumption.js:openRouterCost`), `inquired` (`openrouter-inquiry.js`: the tick asks for
missing amounts every 10 min via the stored generation ids at `GET /generation?id=`, at most 50 per run), `estimated` (catalog price,
`prices.js:estimatedCost` — a row without an id after 1 h, one with an id after 24 h). `prices.js` is only the computation the outer
loop (`costFor`, one number per run) and the tick need. Guard `server/backend/test/usage-routes.test.js` (windows without a fetch,
equivalent, `chatsAdditional`, history, origin, 400, field order = contract).
**`GET /api/usage/openrouter-prices`** is a route of its own so usage never waits for the network: per OpenRouter model used, the
span per 1 M tokens across the active endpoints and the price of the provider of the last response
(`../providers/openrouter-endpoints.js:priceSpan`, 1 h cache, at most four fetches in parallel); an error means `known: false`,
never 0, and holds for 5 min without a new fetch; response after at most `CBASE_OR_PRICES_DEADLINE_MS` (default 10 s). Display
only — billing follows the reported amount. Guard `server/backend/test/openrouter-cost.test.js`.

**Booking:** booking happens on the run paths, not here — `../runs/booking.js` (main turn `bookTurn`, one-off calls
`onceBooking`: EVERY `runOnce` site carries `atConsumption` with a role from `ONCE_ROLES`, row with `source = 'once'`, guard
`server/backend/test/once-consumption.test.js`), `../runs/agents.js:bookConsumption` (subagents with `agent_id`; those ended mid-turn via
`atLateConsumption`, guard `server/backend/test/abort-booking.test.js`) and `../runs/lateBooking.js` (after a crash from the
session files, guard `server/backend/test/crash-late-booking.test.js`). The cache is stored split in `cache_read`/`cache_write`
(NULL = before the split), plus `generation_id` and `cost_origin` (`../store/account.js`, schema "usage-breakdown").
