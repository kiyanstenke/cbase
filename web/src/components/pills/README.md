# `components/pills/` — the header pills

A pill is a small status surface in the header that stays visible on EVERY page and opens on click. The TopNav renders ALL pills itself,
in the order ring · services (Ports · Performance) · browser · VS Code │ runs · bell · design · settings. The scope (which workspace, which
project) comes from `lib/active-scope.ts`, not from props.

| File | What |
|---|---|
| `ActiveRunsPill.tsx` | "Active runs" — what the machine is doing right now, with waiting rows and gate rows (`web/test/credit.test.mjs` reads this file by path). Running dynamic workflows are their own kind (`run.dynWorkflow`: name and state instead of a graph step); it reloads on the global event `dyn_workflow`, the event list lives in the leaf `lib/active-runs.ts` (guard `web/test/active-runs.test.mjs`). Copies that are waiting or being created (field `copies` of the same answer, `copiesFrom`) count in the pill's number (`counts` stays the runs' count), show in the sheet as their own section "Copies" with state, bar, remaining time and an overrun hint (`projects/CopyProgress.tsx`), and a click opens the "Instances" tab with that copy (`lib/project-jump.ts`); reloaded on `project/copy`. |
| `ServicesPill.tsx` | TWO entries: **Ports** (`data-status-ports`, server-rack icon + number of running services, muted at 0) with its menu `data-status-ports-menu` (forwarded, running services with forward/open/×, unregistered, manual forwarding, error row, "All services → Apps"; with a client that knows the exclusive choice the radio list `data-ports-choice` on top) and **Performance** (`data-status-performance`, pulse line + count from `md` up, the icon tinted by the machine via `performanceTone`) with `data-status-performance-menu` (the machine block first, with the gateway per bar split into the part of cbase and the rest; then resources per project with the sum and "measured"). Every service row with a port carries "Share link" (preview links, `components/preview/`). Both menus come from ONE state (`open`: "ports" | "performance" | null) — never both at once. The rules live in the leaf `lib/services-status.ts` (guard `web/test/services-status.test.mjs`): the pill computes and colors nothing itself; the explanation is in the file header. Closed, it asks `/api/project-resources` with `disk=0` — the folder size (`du` over every project folder) is measured only when the PERFORMANCE menu opens. |
| `AgentBrowsersPill.tsx` | Icon + number of the browsers an agent steers (Playwright), viewer window; visible only while there are any. It opens the window through `openBrowserWindow` (`lib/browser-choice.ts`, the same call as the button in the browser section of the right chat bar) and by PROFILE (`windowForSession` → `/browser/?profile=<folder>`): by session id the window would stay at "gone" after the agent's next run. |
| `VsCodePill.tsx` | VS Code Remote Tunnel into the container (`CBASE_VSCODE_TUNNEL=1`). When connected, additionally the group "Projects" (`data-vscode-projects`, row `data-vscode-instance=<id>`): per relocated project the main and every copy that is ready, from the field `projects` of the tunnel answer (only in project-box mode); per row ONLY the desktop link — Dev Containers "attach" behind the tunnel (`lib/vscode-tunnel.ts:containerLink`, guard `web/test/vscode-container-link.test.mjs`); vscode.dev cannot do that. Below it ONE sentence: the window runs in the container, processes there can ask for the Mac's git/ssh access, clearing away a copy AND re-creating the project container close it hard (idle does not count an open window), `dev.containers.dockerPath` = `docker`. iOS has no VS Code pill. |

Callers from outside: ONLY `TopNav.tsx`. No page under `app/` imports a pill (guard `web/test/statusBar.test.mjs`). NOT here:
`NotificationBell.tsx` and `ThemeToggle.tsx` (header, but not pills in the sense of this family).
