# `components/outerloop/` — outer loop in the web client

Outer-loop agents are user-managed background agents that watch chats and write one note per run. The **summarizer** is the one fixed
built-in agent per workspace (only its notes are visible to other agents); the **agenda keeper** is the second fixed one: it catches up the
agenda of a watched chat when the main agent forgets. Three origins: workspace, project, chat.

"Fixed" (no delete, "Reset to template", "new template", the mark in the editor) hangs on `fixed` (summarizer OR keeper OR timeline agent),
never on `summarizer` alone. Only the keeper has the toggle "Mark changes" (`markUpkeep`, a 400 for any other agent) and the tally
"12 changes · 10 standing · 2 corrected" (standing = open + confirmed). Its mark in the agenda is drawn by `chat/AgendaPanel.tsx` (a ring on
the status symbol that stays after the main agent and says what happened afterwards). Guard: `web/test/outerloop-keeper.test.mjs`. Built
against the JSON forms of `lib/api/outerloop.ts`.

**Not here:** the ways to the server and the forms (`lib/api/outerloop.ts`), the tab keys (`lib/coding-tabs.ts`), the subagents page
(`components/AgentsPane.tsx`).

**Three questions.**
- *Why does an agent show "off" on a chat although it is on?* → `OuterLoopChatSheet.tsx` shows the server's `source` (`outerloop/activation.js` in the backend): row off, not default (chat older than `defaultNewSince`), ineffective, archived.
- *Where does the tool catalog come from?* → from the server (`GET /api/workspaces/:wid/outer-loop`, `catalog`); there is no second list here.
- *Why no stop button?* → a run lasts seconds to minutes; it is aborted by deleting the agent or the chat.
