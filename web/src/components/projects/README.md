The calculations live in `web/src/lib/`: `project-layout.ts` (pure, in the gate via `web/test/project-layout-plan.test.mjs` and the
fixture set `server/backend/test/fixtures/layout-plan/`), `project-upload.ts` (reading, POST body, upload with `operation`/`offset`),
`project-setup.ts` (rows and locks from `setup`/`detection`).

Questions this folder answers:

- **Where does an uploaded file go?** `lib/project-upload.ts` `creationBody` → `targetOf(plan.mapping[source], origin)`. The server
  writes ONLY into the source's staging area (`.cbase-source-<seq>/<target>`); placement brings it to its place.
- **Why does the row say "waiting for upload" while I am uploading?** The server's row is hidden while THIS tab uploads the source
  (`runs` in `ProjectsPane`); another tab sees "upload running" until the last chunk request is older than 60 s (`UPLOAD_QUIET_MS`).
- **Where does "Resume upload" get the preview's moves from?** The mapping per project and source lives in the browser
  (`rememberMapping`, localStorage); if it is missing the default applies (folder → `<target>/<path>`).
- **Why does an aborted later upload show "Upload interrupted" instead of nothing?** Abort halts; the operation stays with the server
  and "Discard" on the row deletes it. An operation ended in THIS tab counts as interrupted at once (`retroactiveDisplay` `ended`).

The row of a layout job (waiting · running · no longer fits · half taken over) is computed by `lib/project-setup.ts` `layoutRow`
from the project's `layout` field. After taking over, the code tab re-derives its tabs (`components/CodePane.tsx`, calculation
`lib/layout-paths.ts`).

Not here: the clone itself (submodules, LFS) is run by the server in the container (`projectbox/setup/clone.js`), as is the placement
of later uploads (`projectbox/setup/upload.js`).
