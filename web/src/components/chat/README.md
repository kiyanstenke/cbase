# `components/chat/` — the coding chat (`/workspaces` → Chats) in the web client

The `ChatPane` family: the chat component and everything that was cut out of it so that no file passes the line guard
(2,000 lines). The cut is mechanical (bodies moved, not refactored): what was a closure of the component is now a prop, an
argument or a getter.

**Not here:** the UI kit (`components/CbKit.tsx`, shared by all pages), the format helpers (`lib/chat-format.ts`) and the
**shared chat set** that stays in `components/` (`AssistantBlocks`, `AskCard`, `SlashPalette`, `ComposerStrip`,
`LimitStrip`, `CbSendButton`, `AgentBar`, `ArchiveBar`, …). Named exception: `RunDisplay.tsx` lives HERE, next to its
ingredients (`ChatCatalog`, `ChatIcons`).

## Questions this folder answers

1. **Where does a stream event become a bubble?** In `chatBubbles.ts` (`apply`, the switch, over the pure mutators before
   it); `ChatPane.tsx:onEvent` is the wrapper (snapshot `reducerCtx()`, `setBubbles((prev) => reduceChatEvent(prev, evt,
   ctx))`, `streamRef.current = streamAfterEvent(evt, ctx)`, then the side effects per event kind).
2. **Where is the composer, the list, the stage, the right bar?** Each in its own file (map below); `ChatPane` passes props
   by their own names and keeps what the global popover closer, `send`, the stage or `open()` touch.
3. **What is NOT in this folder?** Kit, shared chat set, format helpers (see above).

## Rules

- The family files export through a closing `export { … }` or at the place of declaration and import NOTHING from
  `ChatPane.tsx`; **no export from `ChatPane.tsx` except `ChatPane` itself**, otherwise component and helpers import each other.
- Whoever adds a prop to a family component enters it in its props type (in the right group), in the destructuring and in the
  call in ChatPane; `web/test/composer-contract.test.mjs` counts both sides (composer: required group and picker group; list,
  stage and right bar: all required, one line per value, no context). A new event that changes bubbles gets its branch in `apply`
  AND an entry in `IN_REDUCER` of that test; one that only sets state goes into the wrapper and `ONLY_WRAPPER` (waiting phase or
  background work: `chatBackground.ts:backgroundEvent`).
- The reducer reads no ref and no clock: what it needs is in the `ReducerCtx` snapshot, taken at the time of the event.
- `web/test/credit.test.mjs` reads the family BY PATH (`readChatPaneFamily`); whoever moves a file or the role "limit" /
  `<LimitRow` / `<LimitStrip` updates its `lies()` line.
- The model catalog stands in THREE places: server `providers/connectors/{claude,codex}.js`, `ChatCatalog.tsx` (fallback and
  `/model` aliases), iOS `Chat/ChatViewModel+Slash.swift`. The picker knows no free text.
- A subagent survives its turn: `run_done` clears only the foreground (`lib/agents.ts:backgroundAfter`). Its report arrives as a
  completion notice stored under the role `user` and recognised by its start `<task-notification>`
  (`lib/completionNotice.ts:isCompletionNotice`); `buildBubbles` and `startInjectedTurn` show a separator instead of a bubble.
  The third kind under that role is the message of another agent (start `<cbase-message`, `lib/agents-message.ts:messageCard`):
  a card, no bubble, closes no question. Guards: `reducer.test.mjs`, `streams.test.mjs`, `agents-message-binding.test.mjs`.
- A dynamic workflow shows in the coding chat in four places: start and end marker in the history (role `workflow_marker`,
  `lib/workflow-marker.ts` → `SeparatorRow`), the approval card without opt-in (`workflow_approval`), the progress tree as a card
  in the "Background Tasks" list of the right bar (`chatDynTree.ts` → `ChatRightSidebar` → `AgentBar` → `DynWorkflowCard`,
  computation in `lib/dyn-tree.ts`), and the report as completion notice. Start by `/name` does not exist in the web client.
- An archived chat is opened through `chatArchive.ts:openTarget`; it stands in no list, `archiveChat` carries its metadata, and
  `ChatPane` renders `<ArchiveBar>` instead of `<ChatComposer>` as child of the stage.

## Test benches by hand (not in the gate)

Checked by hand in a real browser: slash picker, draft, composer strip, limit strip, autocompact, text size,
stream healing, chat scroll bar, history edge, dynamic-workflow tree and library. They measure `web/out`, so build
first and never run them in parallel. Mobile counterparts: `mobile/CbaseMobile/Chat/`.
