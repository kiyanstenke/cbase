# `CbaseMobile/Shell/` — the shell of the iOS app

Folders are organized by the place where the user OPENS a view. This folder holds only what the shell itself is.

| File | What |
|---|---|
| `CbaseMobileApp.swift` | the `@main` entry point |
| `RootView.swift` | boot splash (lens + wordmark, like `BootSplash.tsx`), sign-in, hand-over to the shell (with the older-server notice over it), the blocking screen of a server that needs a newer app |
| `ServerCompatibility.swift` | the app's two answers to a server of another API level (`Models/ApiContract.swift`): `NeedsNewerAppView` (phase `.needsNewerApp`, blocking instead of the sign-in: title, text, App Store button `needs-newer-app-store`, the way to another server) and `OlderServerNotice` (a banner over the shell, dismissible with ✕, once per server address and server build — `SessionStore.olderServerNoticeDue`). UI tests `ServerApiUITests` |
| `AppShell.swift` | the mobile shell: header (workspace/project + ports and performance buttons + usage rings; when space is short the number on the performance button gives way first, then the name — `.layoutPriority(1)` on the scope picker, rings `.fixedSize()`, otherwise the rings' "12 %" wrapped to two lines on the iPhone 17), content area down to the bottom edge (below it only the home-indicator strip, `restingBottomInset`; outside a chat a keyboard's padding stands there while a keyboard is up, taken from the ANNOUNCED notification `KeyboardAnnouncement.frame` (`Chat/ChatStageController.swift`), not from SwiftUI's keyboard region, which jams after a keyboard that went away without animation in the chat — by about the 100 pt of the `KeyboardGripAccessory`; the root therefore always ignores the bottom edge), the three places (Coding · Apps · Profile — a segment bar at the top of the RIGHT drawer), both drawers with their swipe recognizers; holds the `ServicesStatusModel` (start in `.task`, restart on `state.scopeKey`, stop in `onDisappear`) |
| `LeftDrawerBody.swift` | content of the left drawer — per place. Coding: without a workspace the workspace list, otherwise per category (chats and scheduled → `ChatsSidebar`, context, code, terminal, browser, projects, …). Apps and Profile each have a drawer of their own; Coding → Skills goes through `ItemsSectionSidebar` (Own · Adopt) like agents, workflows and MCP |
| `CategoryContent.swift` | content area of the workspace view: one mobile version per coding category (switches to `Chat/`, `Code/`, `Workflows/`; `.workflows` switches per `state.workflowKind` to `Workflows/WorkflowsPane.swift` ("Graph") or `Workflows/DynWorkflowsPane.swift` ("Dynamic"), renewed per scope and kind; `.scheduled` → `Code/ScheduledPane.swift`). `SelectedChatHost` fetches a chat that is not in `model.chats` after a reload via `GET /api/chats/:id` (`fetchPerId`) and holds it, so an archived chat opens with its bar instead of "Chat not found". Only a chat of THIS workspace with `kind == "normal"` is opened. "Not found" appears only on a 404 or a foreign kind; any other error shows "Try again" |
| `ServicesStatus.swift` | the PURE calculation `MachineStatus` + `ServicesRules` (thresholds `warn` 0.7 / `danger` 0.9, `machineLevel` over RAM · load per core · disk — swap does not count —, `sum`, `measured`; bound to `web/src/lib/services-status.ts`, hence without SwiftUI/`L`/`APIClient` and with the closing brace in column 0) and `ServicesStatusModel` (query every 20 s: `/api/project-services`, `/api/project-resources`, `/gw/host` — and ONLY that: the app is always in gateway operation and, like the web, does not read the resources' `host` field —, `/api/browsers`; the resources with `disk=0` while closed, immediately without it when the menu opens — only for the PERFORMANCE popover; `resourcesLoaded` + `ServicesRules.measureRow`: no "measured" line before the resources' first answer). Also `MachineStatus.cbase` (decoded optionally — an older gateway does not know the field) and `CbaseRules` (cbase's share per bar: `part` — value / total, clamped to the occupied part —, `progressBar` — the split; twin of `cbasePart`/`progressBarParts` on the web, bound by EXECUTION in `web/test/cbase-share-binding.test.mjs`, macOS only; a type of its own because it reads the swap, which `ServicesRules` must not know) |
| `ServicesButton.swift` | TWO header buttons on EVERY tab: **Ports** (`server.rack` + number of running services, muted at 0; identifier `status-services`, value = number) with its popover `status-services-menu` (services — tapping opens Apps with the project —, agent browsers, "All services → Apps"; asks for nothing) and **Performance** (`waveform.path.ecg`, red/orange by the machine via `performanceColor`, otherwise `.secondary`; plus the CPU of the measured services if the header has room — `ViewThatFits`, on the iPhone 17 with two rings the symbol alone; identifier `status-performance`, value = CPU) with `status-performance-menu` (the machine FIRST, with a gateway measurement two-part per bar: cbase solid, the rest of the occupied part lightened, below it "cbase <value>", legend `status-cbase-legend`; then resources with "measured: x of n", instances, "No measurement."; ONLY this popover reports to the model, `menu(open:)`, and asks with folder size). One state `open: StatusMenu?` — never two popovers at once. Nothing before the first load. More identifiers: `status-services-row-<id>`, `status-agent-browsers`, `status-services-apps` (ports), `status-services-machine`, `status-services-sum` (the numbers, absent without a measurement), `status-services-resource-<projectId>` (per counted row — exactly `Sum.projects`, the counting rule lives only in `ServicesRules.sum`). If services run and none is measured, the Resources section still shows, with "measured: 0 of n services" and no numbers — but only once the resources have answered (`model.measureRow`). The machine is always called "Server"; without `/gw/host` none is shown (Performance). Guard `web/test/statusBar.test.mjs`, UI tests `ShellUITests` (four services tests, plus `headerWithoutWrap`: rings on one line, name · ports · performance · rings without overlap) |
| `PreviewLinks.swift` | PURE rules `PreviewRules` (an instance target of a link — `.b`, `.instance(name)` or `.unknown`, then NO offer; runtimes 1/7/30/unlimited, default 7; remaining time rounded down, in days from TWO days on like the web; `assignment` of a link to its service row over project, instance AND service like `linkOfTheRow` on the web, links on another instance sit below and name it; `limitReached` — all bound in `web/test/preview-rules-binding.test.mjs`, run with `xcrun swift`), the model `PreviewLinksModel` (`GET /api/preview-links` on opening and on `AppState.previewTick` = SSE `vorschau/link`, never on a timer; **a 404 means "the server does not know it" — silently nothing, also in the UI-test fixture**; create with all four keys, revoke) and the pieces `PreviewShareButton` (menu on the service row in the ports popover, without access the way to the settings, at the plan limit the active links to revoke) and `PreviewLinkRow` (address, `ShareLink`, copy, revoke with confirmation, remaining time) — used by `ServicesButton.swift` (the model lives there in the BUTTON, not in the popover: a notice survives closing, an error that arrives afterwards sets `errorUnseen` = red dot on the button) and `Settings/NgrokSettings.swift`. Identifiers `preview-*` at the top of the file |
| `NotificationsView.swift` | the notification center (bell): list of service events and notices, a tap opens the chat (`chatId`) |
| `AppsPage.swift` | Apps tab ("Projects & stacks", no port view): per project its stacks (main and copies, from `/api/projects` and `/api/project-resources?disk=0`; clearing away opens the delete sheet `CopyDeleteSheet` from `Code/CopyDelete.swift`, the DELETE lives only there) and the services compactly with start command, across all workspaces; port conflicts from `GET /api/ports/conflicts` (per project, an error keeps the last state — never counted itself; guard `web/test/apps-conflicts.test.mjs`) |
| `ProfilePage.swift` | Profile tab: account, server (administration for admins); `ProfileSubView` carries only `.account`. Agent instructions live under `Code/AgentInstructionsPane.swift` |
| `PushNotifications.swift` | the UIKit bridge for APNs (`UIApplicationDelegate`) |

Not here: session and app state (`Models/SessionStore.swift`, `Models/AppState.swift`), the building blocks and tools
(`Kit/`, including the DEBUG probe `PerfProbe`), the chat family (`Chat/`). A new view goes into the folder of its place,
not here.

**The three most common questions:**
- Where are the three places switched? → `AppShell.swift:RightDrawer` draws `HomeTab.allCases` as `CbSegments` (identifiers `home-tab-<tab>`) and calls `state.select(tab:)` — the state itself lives in `Models/AppState.swift`.
- Where is the drawers' swipe recognizer? → `AppShell.swift:HorizontalPanReader`, the pan over the whole window; it freezes scroll views while panning and must not trigger buttons.
- Where does a push notification arrive? → `PushNotifications.swift:CbaseAppDelegate.userNotificationCenter(_:willPresent:…)` decides banner/sound depending on whether the chat is currently open; the tap on the notification goes through `…didReceive response:`.
