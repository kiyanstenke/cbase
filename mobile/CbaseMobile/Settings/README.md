# `CbaseMobile/Settings/` — the settings

One file per settings page, named as on the web (`web/src/components/settings/`).

| File | What |
|---|---|
| `SettingsView.swift` | The list of pages, in the order of the desktop; below it the About footer (licence, source, privacy, `settings-about-version` "App <version> (<build>)" and `settings-about-server` "<build or version> · API <level>", "unknown" for a server without an API level; re-read on opening via `SessionStore.refreshGatewayInfo`). |
| `ProviderSettings.swift` | Providers: `ProviderSettingsView`, `AuthLoginConsoleView`. Exactly three cards: Claude, Codex and the FIXED OpenRouter card (set or remove the key, the two privacy toggles, default model from the catalog with search; `GET/PUT/DELETE /api/openrouter`, PUT always with BOTH toggles), plus the default effort level per provider (`defaultLevel`, `PUT /api/default-effort`, entries from `EffortSelection.entries` without an empty entry: the default IS a level). |
| `AgentModelSettings.swift` | Models of the internal tasks, with an effort level per task (`EffortSelection` showing "Default · <level>" on the row's EFFECTIVE model from `GET /api/agent-models`). |
| `AgentHooksSettings.swift` | Hooks (`HooksSettingsView`; the three blocks next to it live in `HooksExtras.swift`). |
| `UsageSettings.swift` | "Usage" as a push list of the five subpages of the contract (`UsageContract.usageSubpages`: Overview, Claude, Codex, OpenRouter, At limit), built like `IntegrationsList`; `start` opens the subpage on a jump `usage:<subpage>` (`AppState.settingsJump`, the header rings). Also the blocks the subpages share (window bar, "since HH:MM", equivalent value, tokens, per model, background per role, chats + "and N more", history bars), "At limit" (`UsageAtLimitView` = `AutoContinueSection`) and, ONCE, the ring calculation per subscription provider (`subscriptionQuota`). |
| `UsageOverview.swift` | Overview: per subscription provider ring + 30-day equivalent value, OpenRouter 30-day cost + credit, number of waiting items. Each row leads to its subpage; each number loads on its own (`try?`), a missing one shows "—". |
| `UsageSubscription.swift` | Claude / Codex: windows `session · week · 30d` (without a snapshot "Last 5 hours" / "Last 7 days"), equivalent value as the main number, tokens with cache read/write separated, subagent share, per model, background, chats, history; for Claude also all limits of the last snapshot (`/api/usage/claude-limits`, "measured N min ago") and the credit balance (`/api/usage` → `credit`). |
| `UsageOpenRouter.swift` | OpenRouter: credit (`known: false` ⇒ no amount), cost `30d · total` with its source (reported, queried, estimated, unknown), per model with price range per upstream and "last" (`/api/usage/openrouter-prices`), per chat, background (also outer loop), history. |
| `WorkflowsSettings.swift` | "Workflows" in the "Behavior" group after "Chats" (contract `WORKFLOWS_PAGE`): cap and size guideline of the dynamic workflows (`WorkflowCapSection` with `WorkflowSizeRow`). |
| `WorkflowCapSection.swift`, `WorkflowSizeSection.swift` | Each with its own state and loading like `AutoContinueSection` (if one route fails, the rest of the page stays): the per-user cap on concurrent workflow agents (default 8, `GET`/`PUT /api/dyn-workflow-cap`; the per-run cap is not adjustable, the server supplies its number) and the size guideline (`GET`/`PUT /api/dyn-workflow-size`, the levels come from the server). Web counterpart: `WorkflowCapGroup` and `WorkflowSizeRow` in `WorkflowsSettings.tsx`, same wording; `web/test/settings-form.test.mjs` holds the routes and level labels of both clients. |
| `SaverSection.swift` | "CPU saver" on the "Workflows" page: ONE toggle, `GET/PUT /api/cpu-saver` (`{ enabled }` required); web counterpart `SaverGroup` in `WorkflowsSettings.tsx`. |
| `ChatSettings.swift` | The "Chats" page in the "Behavior" group (`ChatSettingsView`): "Archive chats automatically" (`ChatAutoArchiveSection`, `GET`/`PUT /api/chat-auto-archive` with `{ enabled, days }`, BOTH fields in every PUT, days 1–365 as field and stepper, the stepper throttled). Own state and loading like `WorkflowCapSection`; unloaded shows "—" instead of a toggle set to OFF; a save error stays as a line and the display falls back to the last confirmed state. Every change goes through `change` (the round is counted when CHANGING, the throttle cancels); the PUT reads the then-current state when it FIRES and waits for the previous PUT, so the last change wins. `ChatAutoArchiveDoc` requires both fields: an answer without them is a load error, not "off, 30 days". Guard: `web/test/ios-archive.test.mjs`. Not to be confused with the per-chat settings (`Chat/ChatSheets.swift:ChatSettingsSheet`). |
| `BrowserSettings.swift` | Browser. |
| `LanguageSettings.swift` | Language, with `Notification.Name.cbaseLanguageChanged`. |
| `EnvironmentSettings.swift` | Server environment (gateway operation); the READ-ONLY "Resources" group (RAM limit with usage bar, CPU priority, CPU upper limit): ONE fetch of `GET /gw/env`, two readings (`GatewayEnvInfo`, `AdministrationOwn`); without `resources` the group is absent. |
| `AdministrationSettings.swift` | "Administration": users and resources per user container, admins only. The fourth group in `SettingsView`, under the ONLY condition of the list (named in `web/test/settings-form.test.mjs`), also reachable from the profile (`Shell/ProfilePage.swift`, as a sheet). `AdministrationModel` (shared by list and user page, only the latest answer counts, 15 s tick while one of the pages is open), `AdministrationSettingsView` (server with reserve mark, all users) → `AdministrationUserView` by push (draft of the limits: stepper, `CbSegments`, selection; role, password, locks, container actions, delete with or without data), sheets Create and Password. Models and routes in `Models/AdministrationModels.swift`, texts in `Kit/LocDEAdministration.swift`; web counterpart `web/src/components/settings/AdministrationSettings.tsx`. |
| `IntegrationsSettings.swift`, `IntegrationsList.swift` | GitLab accounts; below them the "ngrok" group from `NgrokSettings.swift`: authtoken and optional API key, values never come back, `PUT` with BOTH keys and `null` = unchanged, 404 = group absent; plus the mode sentence and the preview links with history. |
| `NotifySettings.swift` | Notifications per kind and per chat. |
| `AutoContinueSection.swift` | "Continue automatically at the limit" + credit gate; the chat reads the models too. |
| `HooksExtras.swift` | Permanent approvals, web search, read aloud. |
| `AccentColorSection.swift`, `AppearanceSettings.swift` | Appearance. The theme is `Kit/Theme.swift` (`ThemeStore`), the chat font `Kit/ChatTypeface.swift` (`ChatTypefaceStore`), the text size `Kit/TextSize.swift` (`TextSizeStore`, for the whole app; `AppearanceSettings.swift` has a fixed-geometry step bar at the top: A−, five dots, A+, tapped, not dragged). |

Trap: the input row of the permanent approvals (`HooksApprovalsSection`) scrolls itself to the middle after the keyboard appears (`ScrollViewReader` in `AgentHooksSettings.swift`); the list's keyboard avoidance otherwise pushed it behind the glass header bar on first focus. Held by `SettingsUITests/testHooksKeyAndPermanentApprovals`.

Not here: the appearance stores (`Kit/Theme.swift:ThemeStore`), the language tables (`Kit/LocDE*.swift`) and the per-chat settings (`Chat/ChatSheets.swift:ChatSettingsSheet`).

**The three most common questions:**
- Where is a provider signed in? → `ProviderSettings.swift:AuthLoginConsoleView`, the PTY bridge for `claude auth login` / `codex login`, the same as on the desktop.
- Where are the two limit toggles written? → `AutoContinueSection.swift:toggle(_:)` (`PUT /api/auto-continue`) and `gateToggle(_:)` (`PUT /api/credit-gate`): two routes, two defaults; both require the field `enabled` (400 without).
- Where is the language switched? → `LanguageSettings.swift:LanguageSettingsView.apply(_:)`: `Loc.persist`, `PUT /api/ui-lang`, then `.cbaseLanguageChanged` to all views.
