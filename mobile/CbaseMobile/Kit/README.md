# `CbaseMobile/Kit/` — the building blocks of all pages

| File | What |
|---|---|
| `Localization.swift` | `L(…)`: key → text, language from `UserDefaults`; the English text is the key, the German tables sit beside it |
| `LocDE*.swift` | the German texts, split over several tables by topic (base, mobile, communication, outer loop, projects, preview, skills, chats, agenda, administration, usage, scheduled, git, instances, …). The tables must not share a key (duplicates crash at start); missing keys show English (`mobile/tools/loc-audit.sh` checks both). Non-literal calls like `L(DynTree.runWord(…))` are invisible to `loc-audit.sh`; `web/test/dyn-tree-binding.test.mjs` checks their words against the tables. Keep each table under 2,000 lines |
| `TextSize.swift` | the text size of the WHOLE app: `TextSize` (five steps = offset −2…+2 Dynamic Type categories from the system size; "Normal" is always the iPhone's size), `TextSizeStore.shared`, `WindowFont` (trait on the window, mounted in `CbaseMobileApp` beside `WindowLevel`), `cbFont(N)` (fixed base size on the curve of the nearest text style, computed by `FixedFont`: no growth above AX2, below L on Body's curve with a 9 pt floor), `@CbMetric` (the same computation for a number: line height, character grid), `Font.symbol(N)` (fixed, ONLY on `Image`), `Font.scaled(_:)` (for `Text + Text` and character grids), and the title steps `cbTitle(.page \| .drawer \| .greeting \| .sheet)` — system font, the hierarchy is carried by weight. New text size: `.cbFont(N)`, never `.font(.system(size:))` and never `.symbol` on text — guard `tools/check/ios-font.test.mjs` with named exception lists |
| `CbRows.swift` | the row language as a kit — lists WITHOUT cards. `CbListRow` (glyph, name, ONE muted short line as `Text`, a paragraph `text` only where it helps with choosing), `CbSign` (SF symbol in a 34-pt circle on `elevated`; markers `.warning`/`.point`/`.pin` with their own label), `OriginKind.characterTone`, `CbRowPress` + `.cbRowPress()` (pressed `marked`, context-menu preview shape, NO `contentShape` in the style), `CbToggleRow` (toggle OVER the row, holds its own room), `CbSectionHeader`, `CbEmpty`, `CbRowSkeleton`, `CbHeaderInfoButton` + `CbInfoSheet`/`CbInfoDot` (the explanation behind the ⓘ), `CbDetailSheet`/`CbSheetAction`, `CbDetailHeader`, `CbOriginRow`, `CbDetailDescription`, `CbDetailField`, `CbMarks`, `CbCodeBox`. The Coding lists use the tile form (`CbTile.swift`) and take only the press, `CbToggleRow`, `CbRowSkeleton(tile: true)`, the ⓘ and the detail sheet from here |
| `CbTile.swift` | the TILE form of the Coding lists (twin on the web: `web/src/components/projects/ProjectForm.tsx`). `CbSituation` (`.quiet` neutral · `.on` green · `.waiting` orange · `.error` red · `.off` muted; `.toggle(_)`), `CbState` (dot plus word), `ProjectTile` (SF symbol in the situation's color on `elevated`, rounded square; 34 list, 44 header, 26 field), `CbTileHeader` (small tile + title + "· name" + figure; `margin` in a list flush with the row tiles), `ProjectField` (header + content), `CbSummary` (the line above the list), `CbTileRow` (tile, name, state, short line, paragraph, chevron; `active: false` mutes name and tile), `CbTileEmpty` (empty as a row with a muted tile). Rows without hairlines in `VStack(spacing: 2)`; the pattern of a whole page is at the head of the file, in full in `Code/McpPane.swift`. The names `ProjectTile`/`ProjectField` stay — `Code/` is written against them |
| `ChatFont.swift` | the type steps of the chat (`chatFont(.caption)` …, `.fixed(N)` = the same computation as `cbFont`); every step carries the chat's typeface (`ChatTypeface.swift`) |
| `ChatTypeface.swift` | the chat's typeface — `ChatTypeface` (Default = SF Pro, SF Pro Rounded, Avenir Next, Helvetica Neue, Charter; only fonts iOS ships, one explicit cut per weight), `ChatTypefaceStore.shared` (device preference). Read by `chatFont` (every history row, code stays monospace), `ChatHighlightableText`/`ChatInlineText` (UIKit text, typeface in the measuring key), `ChatInputTextView` and `ChatTimelineStage` (re-measures everything on a change, like the text size); chosen under Settings → Appearance. No environment value: the history hangs in UIKit cells |
| `SharedUI.swift` | `PaneScaffold`, `PaneCard`, `SectionLabel`, `CbToggle` — the building blocks of the Coding pages |
| `Markdown.swift` | the Markdown renderer of the answers |
| `Theme.swift` | `ThemePreference`, `ThemeStore` (Automatic/Light/Dark), `Metrics`, `WindowLevel` (in dark keeps the parts the system paints in the MAIN WINDOW at the elevated step; sheets set themselves), `ListLevel` (mounted by `CbForm`/`CbList`: the inside of every Form/List at the base step #1c1c1e instead of #2c2c2e — set on the list's `UICollectionView`, found as the tightest collection view containing its own frame, also in landscape), `RowsReason` (the row ground in dark with pressed state — follows `isHighlighted`/`isSelected` of its cell, pressed `selection`; a color as `.listRowBackground` would lose the tap feedback) |
| `CbColor.swift` | the app's palette — twelve roles (`drawer`, `ground`, `surface`, `elevated`, `selection`, `marked`, `edge`, `text`, `textSecondary`, `textMuted`, `primaryButton`, `primaryButtonText`), each light/dark, warm and almost colorless, as `Color` (`CbColor.ground`) and dynamic `UIColor` (`CbColor.ui(.ground)`); plus `CbForm`/`CbList` (instead of `Form`/`List`: ground `ground`, rows `surface` in dark — one palette step —, the system's in light; a row with its own `.listRowBackground` keeps it) and `.cbRows(_:)` (the matching row ground, dark with pressed state via `RowsReason`; the plain artifacts list takes `.ground`). New surfaces, edges and texts only with these, never `Color(.system…Background)` |
| `AccentColor.swift` | the accent: ONE chosen color, light and dark derived from it (same computation as `web/src/lib/accent.ts`), `AccentStore.shared`, `cbAccent()`/`cbAccentRoot()` for the root and every own hosting controller |
| `PerfProbe.swift` | DEBUG only: the aggregating runtime probe (chat history, marker, Markdown) — a tool, not a view |
| `CbKit.swift` | `CbBackButton` (the way out of a category back to the overview), the form of the pages (`CbPane`, `CbOverline`, `CbSeparator`, `CbHairline`), `CbSegments` (no gliding cushion, no spring around the choice), `CbFadeIn`/`.cbFadeIn(at:atAppear:)` with `CbFade` (the ONE motion when a view changes — the new content fades in over 0.15 s), the small controls (`CbMenuLabel`, `CbTextButton`, `CbRoundButton`, `CbSearch`, `CbField`), and the origin of an entry in the project (`OriginKind`, `OriginMarker`, `OriginHeader`; twin of `web/src/components/Origin.tsx`) |
| `CbGlass.swift` | Liquid Glass of iOS 26 (app target 18 — below it the opaque surface): `cbGlass`, `cbGlassButton`, `cbSelection`, `CbGlassGroup`, `CbGlass.inside`/`selected`, the environment value `drawerGlass` (both drawers), the header zone's ground (`CbHeaderVeil`, `headerOverhang`). EVERY bottom sheet in one form: `.cbSheet(.half \| .whole \| .small)` at every `.sheet` site (height, handle and ground ONLY there — glass at every height under iOS 26, below it the opaque `ground`), the environment value `cbGlassSheet`, `cbSheetBase()` instead of `.background(CbColor.ground)`, and `CbStage` (`.cbElevated`, `.cbSurface`, `.cbBase`: in the glass sheet `CbGlass.inside` or nothing). The ONE close button of a sheet: `SheetCloseButton` (glass sphere 44 pt, neutral ✕), in the navigation bar via `SheetClose(identifier:label:locked:)`, in the git sheet before the `PaneScaffold` title; it replaces "Close", "Cancel" and "Done" — `label` tells VoiceOver what it does. A "Save" stays on the right. Guard `web/test/ios-sheets.test.mjs` |
| `CbRefresh.swift` | `.cbRefreshable { … }` instead of `.refreshable` — EVERY pull to refresh. SwiftUI cancels the `.refreshable` task as soon as its work changes an observed property and the view redraws; the request then ended as `CancellationError` or silently without refreshing. The wrapper runs the work in its own task and waits for it. Guard `web/test/refresh-ios.test.mjs` (no bare `refreshable` in app code), on the device `GitUITests` |
| `EffortSelection.swift` | the ONE effort picker of the app — `EffortSelection(effort:empty:providers:provider:model:active:)`, levels only; ultracode is its own toggle beside it, `UltracodeToggle(an:)` in the same file (identifier `ultracode-toggle`, independent of the level, also on a model without levels). Used at six places: chat settings and new chat (each with `UltracodeToggle` below, likewise scheduled) with `empty: nil` (no empty entry), app agents with "Default · <level>" from `EffortLevels.standardLabel` (the caller gives the empty word, already translated), the outer-loop editor and scheduled, and the workflow settings with "Like the chat · new: <level>" from `EffortLevels.standardLabel(…, asChat: true)`. Whether it appears at all is decided by the block ITSELF (no picker with `caps.effort` off or a model without levels — `EffortLevels.noLevels`); `active` is the globally active provider an empty provider computes with. The entries are computed by `EffortSelection.entries`, the levels and the "runs as …" marker still by `EffortLevels` (`Models/Models.swift`). No identifier — the picker is found by "Effort". Bound to `effortEntries` (`web/src/lib/effort.ts`) in `web/test/effort-ios.test.mjs` (runs `entries` with `xcrun swift`; holds that no picker iterates `EffortLevels.selection` itself — named exception `/effort` in `Chat/ChatViewModel+Slash.swift`). `/effort ultracode` flips the toggle there, before the "without levels" switch and without touching the level |
| `ModelSelection.swift` | the ONE model choice with search — `ModelChoice(title:groups:selection:value:front:rear:menu:)` keeps the caller's menu as long as OpenRouter is not among the groups; with OpenRouter (whole catalog, hundreds of models) it becomes a row that opens `ModelSelectionSheet` (search over name and id, a section per provider, identifier per row `model-choice-<value>`). Used by every model choice of the app |

Counterpart on the web: `web/src/components/CbKit.tsx` (kit of ALL pages). On mobile the HIG applies — whoever needs a surface, a segment bar or a search field takes these blocks instead of own cards.

Not here: the pages themselves — the Coding panes live in `Code/`, the chat family in `Chat/`; the kit supplies the form (`CbPane`, `PaneScaffold`), not the content. And no models (`Models/`).

**The three most common questions:**
- How do I get a translated text? → `Localization.swift:L(_:)` — key in, text from the table of the chosen language; the key must stand in one of the `LocDE*.swift` tables (`mobile/tools/loc-audit.sh` checks this).
- Which blocks for a page? → `CbKit.swift:CbPane`, `CbSegments`, `CbBackButton` — surface, segment bar, the way back; the frame of a Coding page is `SharedUI.swift:PaneScaffold`.
- Where is the appearance chosen? → `Theme.swift:ThemePreference` and `ThemeStore` — Automatic/Light/Dark; the page for it is in `Settings/`, the switch in the right drawer (`Shell/AppShell.swift`).
